# G重新训练：Flow起点×训练历史四组对照

日期：2026-09-29。状态：训练接口已实现，数据清单已冻结；真实片段试跑与队列启动状态见[queue.json](../../exp/egorecover_g_pretraining/v1/queue.json)及[LOG](../../LOG.md)。本文末尾列出实际执行细节，不能将方案预算当作完成状态。

理论与文献依据见[研究分析](../design/g-pretraining-review.md)。本轮训练历史条件G；此前完成的[E0–E3](e7-minimal-ablation.md)是冻结原E7的窗口×地面对照，两轮编号和结果分别管理。

## 1. 要回答的问题

1. 给定相同身体历史、P预测和视觉/轨迹，使用P预测作为Flow起点是否优于Gaussian起点？
2. G训练中见过预测历史，是否能在实际闭环中更准确地纠正历史误差？
3. 两种改动是否互相促进，还是其中一项已经足够？

本轮不单独估计过去观测分支、地面、P架构、FK权重或初始化方式的贡献；这些全部固定。四组能回答上述两个因素，不能将收益分别归功于所有共同修改。

## 2. 四组定义

记H为目标帧之前20帧身体历史，μ=P(H)，ε为标准高斯噪声。所有组都把H、μ以及截至当前的图像/头轨迹输入G。

| 编号 | Flow源 | 训练历史 | 对照目的 |
|---|---|---|---|
| T0 | ε | 100% GT | 改进后架构的基础训练组 |
| T1 | μ+ε | 100% GT | T1−T0检验理想历史训练下的先验起点 |
| T2 | ε | GT与预测历史混合 | T2−T0检验Gaussian组的历史适配 |
| T3 | μ+ε | GT与预测历史混合 | T3−T2检验混合训练下的先验起点；T3−T1检验History组的历史适配 |

σ统一为1.0，首轮不调σ。Gaussian组仍接收相同μ条件，避免把“是否看到P预测”与“源分布选择”混为一谈。

GT/混合是训练设置。**四组的主要评价都使用模型预测历史，并逐帧提交自身输出**；不拿T0/T1的GT-history成绩对比T2/T3的闭环成绩。

## 3. 所有组共同的架构与物理协议

### 模型

- 10Hz；H包含t−20…t−1；每次只生成t的一帧243D身体状态。
- 保留E7 Transformer骨干、x0预测和Euler求解器，训练原骨干及新增条件分支的全部参数。
- 补齐过去20帧及当前帧的DINOv2特征、18D头轨迹条件；特征提取器固定，投影层随G训练。禁止读取t之后的观测。全注意力仅覆盖已可见的21个物理时刻。
- P固定为常速度＋残差，无显式速度、无Two-Forward。P训练若需重做仍使用geometry=1、FK=0；四组绑定同一个P checkpoint。
- 本轮只训练clean、图像与轨迹均可用的a11条件；共同清单排除不可用目标窗口，不按组过滤。暂不混入四动作随机屏蔽、Q或故障训练。
- 四组从同一原E7 EMA初始化；新分支按现有规则零初始化。重新建立优化器和EMA，不恢复原训练动量。零初始化不代表修改后的网络与原E7函数等价。

### 地面、参考系与体型

- 使用数据提供且通过审计的floor_height。零值/缺失先根据元数据确认有效性，无法确认则排除并统计；禁止静默退回“平均头高”或按评价帧GT脚高度计算。该设定是已知地面的研究条件，不声称完成部署地面估计。
- 在线G统一保留现有稳定的planar参考协议，禁止某组改为自由SE(3)；同一floor下重新编码H、轨迹、μ和target。它与原E7完整SE(3)解码仍有差别，需在结果中注明。
- 历史替换后，target的参考增量必须从该历史最后一个已提交reference指向当前GT reference；过去轨迹也使用同一套参考规则重新编码，不能拼接旧缓存中的归一化向量。
- 每段前20帧通过同一冻结原E7、正确地面和原生编码/解码生成公共启动状态；20帧结果只在第19帧结束后可用，正式从t=20输出。这个2秒启动延迟单独报告。
- 用该启动结果的预测β均值作为beta_boot，整个片段固定；不使用GT β或完整测试片段的未来预测β。四组共用同一启动状态、β及噪声。G的β通道仍保留表示监督，主FK指标统一使用beta_boot。
- 新协议下重新评价已有P。发现协议不兼容时在train上重训同结构P，dev选点，然后冻结；不把旧34.099mm当作新协议成绩。旧bootstrap/replay缓存不直接混用。

planar和固定β有利于保持现有在线实现的一致性，但这轮不验证它们优于原E7处理。共同的原生解码核对和往返检查必须先通过；不能把“内部检查通过”当作精度证据。

## 4. 数据、教师历史与公平性

### 数据范围

- 训练目标是使用可获取、可审计的官方train数据，至少覆盖已有192个take的有效部分，再纳入新增合格take。四组使用完全相同的冻结take/片段/目标帧清单；实际数量和小时数由准备报告填写，不预先虚报。
- 10Hz、非重叠200帧片段；目标t=20…199。同一原始片段的不同变体跟随同一take划分；同take不可跨train/dev/test。
- 默认保留原12个P-dev和12个holdout作为历史诊断保留项，不并入新G/P/教师缓存训练；它们可能被原E7见过，不能作为未见数据泛化结论。
- 从有标签、且未被E7/P训练及本项目历次调参使用过的官方val take中，按动作类别固定划分dev与最终留出集，默认1:1；划分种子20260929。准确名单、数量、初始化训练覆盖须审计后写入manifest。此前用于工程训练/选择的val take排除。
- 如果无法核实未见数据范围，报告评估边界并先解决划分，不把旧12take改名为独立测试。官方无标签test不充当本地有标签评估集。
- 主训练先等概率抽take，再抽片段和目标帧，避免长take垄断。归一化统计固定，来源和哈希入记录；不得用dev/test重算统计。

### 预测历史从哪里来

首轮教师固定为原E7 EMA、正确地面、因果末帧滑窗，最大80帧、Euler10。前20帧采用上述公共启动；从t=20起，教师每次提交当前末帧，状态仅使用其自身时刻可见的观测生成。启动结果最早在t=19可用，不声称启动段逐帧在线输出。禁止用含目标帧或未来帧的离线整窗重建充当过去预测。

教师只在train takes上生成训练缓存，保存世界状态后再按在线协议编码。T2/T3使用同一份不可变缓存和同一采样draw；训练期间不刷新。它包含真实预测误差，但不等同于训练后G的自身历史分布，结论需保留这一限制。

为每个目标键`(take, segment_start, target_time)`生成配对记录：GT历史、教师预测历史、相同原始观测、相同世界GT目标和公共beta_boot。四组共享目标抽样序列；T2/T3只按混合掩码切换该目标的历史，然后重算μ及条件/目标编码。禁止随机换成另一个take或目标帧来实现replay。

缓存与清单绑定：源数据、代码、split、floor、参考系、统计、教师权重、P权重、时间戳和随机种子。训练缓存只含train；dev/test预测只在独立评估路径生成。缓存失败时修复或在开训前统一移除配对记录，不允许各组悄悄使用不同样本。

## 5. 训练预算与阶段

以下是第一版待实测配置，不宣称已收敛，也不将它等同于原E7约84k更新的完整预训练预算。原E7一批监督整窗，本轮一批监督单帧，两者step数不能直接代表相同训练量。

| 项目 | 四组共同设置 |
|---|---|
| 初始化 | 原E7 EMA；全参数G训练；P冻结且eval |
| 更新数 | 每组24,000个optimizer step |
| 有效batch | 64；显存不足时统一用梯度累积保持64 |
| 优化器 | AdamW，lr=8.5e−5，weight decay=0.01 |
| 学习率 | 前1,000步warmup，后续cosine至峰值的0.1 |
| 数值设置 | bf16 mixed；几何解码float32；梯度裁剪1.0 |
| EMA | decay=0.992028；验证使用EMA |
| G监督 | 当前帧x0加权表示MSE，global 198:207权重8；dense geometry=1（scale=0.1m）；FK=0 |
| 采样时间 | 沿用E7 Beta(1.5,1.0)，t_min=0.001 |
| 随机种子 | 62、63、64；每个种子包含T0–T3四组 |

G的geometry=1/FK=0是本轮固定选择，不由P的FK实验推断它必然最优；四组不混入新的损失消融。表示MSE只计一次，不能把Flow内表示项与physical_objective的表示项重复相加。

T2/T3混合概率按optimizer step预先固定：

- 1–2,000步：0%，GT warmup。
- 2,001–6,000步：线性增加到50%。
- 6,001–24,000步：50%。

按整个20帧历史替换，不逐帧随机拼接；T2/T3使用同一掩码。T0/T1始终GT。50%是初始设计值，本轮不根据结果只替某组调参。

同seed共享初始化、目标帧顺序、Flow时间和标准ε，混合选择使用独立随机数流，避免消耗随机数后扰乱其他配对。全程不对P反传。

每2,000步评估固定dev；每组均完成24,000步，保存相同预算末点和dev最优点。最终留出集仅在训练、选点全部冻结后评价。若四组普遍仍在明显改善，统一续训四组并单列追加预算；不只延长暂时落后的某组。吞吐试跑后给出时间预估，当前不填写未经测量的小时数。

## 6. 评价与结论规则

### 主要评价：实际闭环当前帧

各组从公共启动状态开始，每帧由自身最近20帧输出形成H，P给出μ，G生成当前帧并提交。评价t=20…199，主要看t=40…199（历史已全部由本组生成），同时单列启动过渡段t=20…39。

- 主指标：世界坐标SMPL22 Body MPJPE，单位mm，不做根对齐。
- 辅助指标：PA-MPJPE、root、root-relative、头部误差；关节旋转测地角误差以度记录，明确关节集合与计算公式。
- 速度误差使用真实时间差，单位mm/s；同时看动作转折处误差，避免仅靠输出迟缓获得平滑。
- 同一实际H上同时保存P与G输出，计算`P的Body误差−G的Body误差`；正值代表该帧G确实修正了P。不同组的H不同，该量不能单独当作组间公平对照。
- 所有数值先汇总片段，再等权汇总take；跨seed报告均值和标准差。帧不是独立样本，置信区间按take配对bootstrap，并保留三seed配对差值。

### 辅助评价：解释差异

1. 固定教师dev历史单步：四组输入完全相同的H/观测，区分单步纠错能力与闭环历史质量；GT历史单步仅作为上限条件诊断。
2. 相同真实预测历史起点上的4/8步短闭环（0.4/0.8秒），比较误差增长；不额外扩成长程P外推训练。
3. 主结果Euler10；权重冻结后补充NFE=1/3/5，不重新训练、不按组调σ。每种NFE运行自己的完整闭环，报告精度、端到端延迟和P/G分项耗时。
4. 最终评价每seed用三个固定采样draw（1062/1063/1064）；标准噪声按片段和绝对帧配对，启动draw也配对。dev选点用固定draw1062，所有组一致。

原E7因果流程作为共享评价参照，不新增第五个训练组。统一数据、目标帧、地面、关节及beta_boot评分，并另保留其原生窗口β结果，明确协议差别。旧75.254mm和59.958mm只作历史诊断，不能直接填入新数据结果表。

### 四组差值

令M为同预算Body MPJPE，越低越好：

- T1−T0、T3−T2：先验起点的作用。
- T2−T0、T3−T1：预测历史训练的作用。
- `(T3−T2)−(T1−T0)`：交互；负值表示混合历史下先验起点更有利。

同预算末点为主要归因表，dev最优点为实际模型选择表，两者均公开。不预设T3必须胜出，不承诺低于某个mm阈值。若差异跨seed不稳定或区间含0，结论写为证据不足；若仅低NFE改善，结论限于少步推理。共同修改和不同解码协议的影响不由这个2×2表单独识别。

## 7. 实施顺序、资源与交付

1. 审计数据和E7训练覆盖，冻结split及原始目标帧清单。
2. 接通正确地面、公共启动/固定体型及过去观测分支；核对坐标往返、因果性和无GT启动读取。
3. 按新协议确认/训练P，再冻结；制作同目标配对教师缓存。
4. 四组各做短反传与闭环试跑，检查loss量级、加载、目标配对、输出有限性及显存。试跑checkpoint不作为正式实验结果。
5. 完成三seed四组训练，固定选点后评价留出集并汇总结论。

资源方案沿用最近GPU4–7偏好：每个seed一轮，T0/T1/T2/T3分别分配4/5/6/7；同一GPU最多一个本轮训练。实际启动时先检查占用，按可用资源调度，不终止其他任务。共四种配置、12次训练，数据准备、P协议校准和共享教师缓存是公共前置工作，计算成本单列。

复用模块：[G](../../model/history_uniegomotion.py)、[Flow](../../egorecover/history_flow.py)、[物理损失](../../egorecover/losses.py)。旧replay会抽取不同目标的整条样本，旧工程入口还混入四动作训练。本轮使用新增的[配对数据接口](../../egorecover/g_pretraining.py)和独立入口；G通过`past_observations=True`接收过去原始观测，旧接口默认行为保留。

统一入口为[run/g_pretraining_experiment.py](../../run/g_pretraining_experiment.py)，配置为[config/egorecover_g_pretraining_v1.json](../../config/egorecover_g_pretraining_v1.json)。产物统一放`exp/egorecover_g_pretraining/v1/`：

```text
plan.json / queue.json
data/{split,manifest,report}.json
verification/{protocol,causality,smoke}.json
bootstrap/  prior/  teacher_cache/
T0/seed62/ ... T3/seed64/
jobs/  evaluation/
summary.json / RESULTS.md
```

每个run保存resolved config、代码和权重哈希、split/缓存身份、训练曲线、checkpoint及selection.json；逐take指标留在evaluation。未生成的结果路径不作为已存在链接展示。

LOG仅记录设计、正式启动、异常及最终结论，不逐checkpoint写选点。最终必须回答：两种因素各改善多少、三seed是否一致、G是否修正P、低NFE是否受益、相对共享E7参照的收益及协议限制。完成后以可点击RESULTS.md链接登记。

- 在dev中按任务轮流选择固定16take用于每2,000步闭环选点；完整名单在`data/dev_monitor.json`。这是为控制选点评价成本预先固定的子集，不按成绩选择。完整224take是开发保留池；最终222take只在所有模型完成选点后评价。
- 共享P从D_s62的9400步选点初始化，按新协议训练最多2,400步、lr=1e−4、batch32，每400步评价固定dev目标；初始权重也参与选择，因此允许保留原权重。G使用同一选中P。该校准属于公共前置工作。
- 实际有效batch64由4个microbatch16累积。各组GPU使用4/5/6/7，每卡至少24GiB空闲才调度；保留其他进程。
- 核查原E7 checkpoint超参数确认其来源为`e7_x0_global_w8_u84k`、官方EE4D数据。checkpoint没有take级训练清单；仓库训练入口明确train用于拟合、val用于验证。因此本轮留出集应表述为“本项目此次未参与训练和选点的官方val子集”，不能宣称原E7从未验证过的全新测试集。
- 正式训练前重新生成正确地面缓存，不复用旧平均头高坐标缓存。每段检查原生E7解码一致性、planar重编码往返及3个源GT帧的SMPL资产一致性。
- 缓存和评价轨迹保存减去已知地面高度的源世界坐标，地面值记录在manifest对应片段中；预测和GT减去同一常量，因此Body/root等误差与恢复原世界坐标后完全一致。导出原世界轨迹时给z加回该片段floor_height。
- 原E7共享参照采用教师draw1062，分别报告公共启动β与原生窗口β；与G的draw1062配对比较。四组之间主结果仍用三draw平均。启动缓存固定draw1062并在所有组/seed之间共用，三draw变化发生在启动之后。
- 队列顺序：四卡配对缓存→GPU5共享P校准→四组G按seed62/63/64分三轮训练→共享E7参照→留出集评价与汇总。冷加载源文件及缓存生成时间单列，不记为G梯度训练时间。
