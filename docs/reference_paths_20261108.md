# 单帧 GT 干预的 CV 与历史条件路径对照

本轮使用四个窗口的第12,000步 EMA，在相同128个片段、325个干预时刻和3个未来噪声上，将身体姿态干预的影响拆为两条条件路径。所有结果仅评价下一帧；不修改参数或训练损失。

## 对照设计

使用 body_pose 干预：GT rotations/root 经固定体型 FK 生成身体，保留预测 reference/auxiliary、缓存 beta/anchor。这样参考与预测分支的编码只在两个位置不同：

- C：P 重新外推的当前中心 `center[:, -1]`。
- H：被干预的历史时刻 t，W=1 为 `fixed_motion[:, -1]`，W>1 为 `center[:, -2]`。

构造四格：原始条件00、只改变C的10、只改变H的01、两者均改变11。所有格子从独立克隆的原条件出发，共享同一个高斯起点、噪声、观测、参考坐标和冻结权重。11必须逐字段等于完整 body_pose 参考条件。直接使用 prepare 输出的归一化编码，不手工替换世界坐标数组。

每个时刻的三个噪声先配对平均，再按片段和take等权；以下正数为误差下降，负数为恶化。

W=10 的84个坏时刻中，73+5=78个（92.9%）只改变CV条件槽就已经恶化超过1mm；只有5个在单改历史槽时也恶化。其余6个单项均未超过阈值，但组合越过阈值，可能来自小误差叠加或交互，不能仅凭此分类断言非线性。W=3/W=5也呈现相似的CV路径主导坏例模式。

## 为什么不能只看中心几何误差

已有记录显示，W=10 输出恶化的身体干预时刻中，约六成的预测中心几何误差反而改善；中心delta与输出delta的加权相关约0.004。因而中心是否更准，不能代替重建器对中心变化如何响应的诊断。上面的条件路径对照进一步说明，许多坏例确实通过CV条件变化进入G，但并不等于CV中心必然变得更不准确。

单帧GT修正会改变CV隐含速度。对平移而言，若当前修正为δ，而前一帧仍保留原预测，原CV=2*p_t−p_(t−1)，新CV与旧CV相差2δ。旋转也会重算相对转动。此时GT修正与前一帧预测、整段预测历史可能不一致，G对这种新的中心条件可能不够稳健。速度突变/分布适配是合理机制，但本次只定位到CV重算条件路径，未单独分离平移、旋转或训练分布因素。

W=1中，被修正的身体作为固定历史输入，H路径平均带来3.590mm收益；W>1中，它只进入可重建活动窗口的中心历史槽，三组H路径均值很小且略为负。该结果与两种历史读取机制不同相符，但四组权重独立训练，不能据此把所有差异唯一归因于窗口长度。

## 当轮回写的时间顺序

实际链路为 prepare → solve → decode → cache.advance。t+1的当前身体在advance之前已经生成，所以此后是否回写近期过去，无法改变t+1这一个输出。实验复用同一decoded window，分别advance(True/False)，四组所有当前输出均逐元素相同；W=1的整份更新缓存也相同。

这排除的是当轮后置回写对下一帧即时误差的影响。此前回写如何塑造输入历史，以及当轮回写对更远后续输出的影响，尚未由本次h=1对照排除。反事实输入和推理回写切换也不能代替重新训练的架构消融。

## 复核与复现

- 四格的00与11逐例匹配此前原始预测分支及body_pose参考分支，误差差异小于0.01mm；其他条件和参考坐标逐元素相同。
- 同一前缀seed1062、未来seeds1062/1063/1064。分支不写回主前缀。全部比较使用相同检查点、观测、噪声和固定体型。
- 每条路径先独立分表再调用统计模块；每表975次配对响应、325个时刻、128个take。报告包含2000次take簇bootstrap，单训练seed的限制仍然适用。
- 实现脚本：`scripts/diagnose_reference_paths.py`；本地原始报告：`exp/reference-paths-20261108/W*/report.json`，四组紧凑结果：`exp/reference-paths-20261108/comparison.json`。
- 单组复现：`conda run -n egorecover python scripts/diagnose_reference_paths.py --checkpoint PATH --output DIR --data-root DATA --original-root exp/reference-diagnostic-20261108-step12000 --device cuda --shard-index 0 --shard-count 1`。先运行参考分支诊断，以提供逐例复核所需的原始配对响应。
